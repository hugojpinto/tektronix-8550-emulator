# 8086/8088 emulator processor — hardware notes

The 8086/8088 emulator is three boards in the 8301 (I, II and III, slots J14–J16) plus a prototype control probe that carries the processor itself. It is emulated in `emu/src/machine/ep8086.*` (`-ep 8086` or `-ep 8088`). The 1983 diagnostic's 8086 test passes in full on it.

**Established from:**
- **The kernel:** two 1 KB PROMs, `roms/emulator_processor/8088/160-1312-00_emul.bin` (even bytes) and `160-1311-00_emul.bin` (odd bytes). Together they are the 2 KB 8086 program the board runs. They were already in the collection, from the bitsavers `8088_firmware.zip`. Its other files are the 8540 System ROM board's OS/40 support for the same emulator, 160-1359-01 (diagnostic) and 160-1461/1462/1463/1611, in PDP-11 code.
- **The diagnostic:** "8086/8088/8087 DIAGNOSTICS V1.3" on `8550_DIAG.IMD`, Select mode 17. To dump it, run it with `-ep 8086` and use `-dump`, then `build/dasm s2650 F.8301 0 2000 6000`. Its texts are compressed (05 hi lo = insert the string at hi lo; 01 n = n spaces). Module code is next to each module's name; the shared routines sit at 3A2D–3C97 and the generic RAM test at 297B.
- **The board's manuals:**
  - the Installation manual 070-3775-00: what each board holds, and the jumpers;
  - the Emulator Specifics users manual 070-3968-01: AL/MAP/MEM/NOMEM, BK arming, and the note that addresses 8–B are used "whenever a break is generated".

  Both are in `sources/bitsavers/manuals/8086/`.

Inferred points are marked *(inferred)*.

## Boards (070-3775 §1)
- **Board I:** breakpoint circuitry, clocks, address and data strobes, the TTA connectors.
- **Board II:** address latch and buffer, the probe interface, mainframe interface timing, the queue, the mapping RAM and the relocation RAM.
- **Board III:** the data bus interface, the PROM, the function RAM, the command port, the status port and the master register.

## The 2650's side
| Port | Function |
|---|---|
| A7 | **MASTER CONTROL**, R/W. Reads back bits 6–0. Bit 7 reads 1 for a short time after every write, then 0. The diagnostic reads it set right after a write and clear after a ~0.1 s delay (module 10); the emulator uses 1 ms *(duration inferred)*. Bit 0 = processor RESET (81 then 80 is the reset pulse). Bit 1 = RAMINH, which maps the board's RAMs into program memory (below). Bit 2 = trace: break after every instruction. Bit 3 = emulation enabled: a HALT of the 2650 lets the program run. Bits 6–5 = a prototype mode *(inferred: with either set and no prototype, REASON1 bit 7 reads 1, module 13)*. The configuration probe detects the board by writing 7F and reading nonzero |
| 80 | **COMMAND PORT**, R/W. A latch the kernel reads as memory 0800; the kernel's write to 0800 clears it (the acknowledgement). Reset clears it (module 11) |
| 81 | W. Bits 3 and 4: when clear, BK1 and BK2 arm the next breakpoint instead of breaking (module 54). The diagnostic writes 00 then 1E before each run, and 06 for arming. Bits 0–2 not known |
| 87 | **MISC STATUS**, R. Bits 1, 2, 3, 4 and 6 read 1. Bit 0 = 1 for an 8088 probe; bit 5 = 1 for 8 MHz (module 12: "5 MHz 8086 IDENTIFIED") |
| 88 | **BREAK REASON1**, R. 40 trace, 20 SVC, 10 BK1, 08 BK2, 04 BK3, 01 processor reset, 80 see A7<6:5>; bit 1 is not checked. 00 = the 2650 took the bus back |
| 89 | **BREAK REASON2**, R. 02 non-existent memory, 04 write protect, 08 TTA (module 70) |
| 8C | **SVC register** *(inferred: the low byte of the matched cycle's address, the SVC port)* |
| 8D/8E/8F | **PC LAST**, active low: A7–0, A15–8, A19–16 (low nibble) of the last instruction the program started |

**RAMINH (A7 bit 1):** the board's RAMs answer at program memory C000–FFFF in place of program memory. The 2650 reaches them with EE = 03, window 4000–7FFF (module 20).
| Program memory | RAM | Width |
|---|---|---|
| C000–C0FF | breakpoint RAM 1, indexed by A19–12 | 4 bits |
| C800–C8FF | breakpoint RAM 2, indexed by A11–4 | 4 bits |
| D000–D0FF | breakpoint RAM 3, indexed by cycle type and A3–0 (below) | 4 bits |
| D800–D8FF | mapping RAM, one entry per 4 KB block (A19–12) | 4 bits |
| E000–E0FF | relocation RAM, one entry per 4 KB block | 8 bits |
| F800–F81F | common RAM, shared with the kernel | 8 bits |

The 2650 waits for the kernel by polling: write the command to 80, delay, then read 80 until it reads 00 (routine 3A99). Parameters and results pass through the common RAM.

## The kernel (8086 code; command table at 013C, copied to function RAM 1300 at start)
**Kernel memory map** (the processor in kernel state):
- **Opcode fetches** come from the PROM. That covers reset: FFFF0 → PROM 07F0 `jmp short`, which wraps to 0000C `jmp far 0000:0011`.
- **Data, via DS, CS or ES without LOCK:**
  - 0000–07FF: the PROM (its checksums sit at 07F8–07FF);
  - 0800: the command port (0802 bit 0 is read while GO waits, below);
  - 1000 and above: the 4 KB function RAM. Module 33 reaches it at 2000, so the decode uses any of A15–A12.
- **Stack-segment accesses** go to the 32-byte common RAM (A4–0). The kernel's parameter block is `[bp+n]` with SS = BP = 0.
- **A LOCK prefix marks an access to the user's side:** `lock mov [es:bx]` is user memory, `lock in/out dx` is user I/O. A **LOCKed IRET** returns to the user's program: its three pops come from the common RAM, and the board switches to user space for the fetch that follows *(the switch point is inferred, from the GO path 036B–0386)*.
- **Port 0:** IN returns the low bits of the first stack write of the last break, which locates the frame the NMI pushed. OUT at reset only.
- **Vectors:** INT 1 → 0196 (trace; status 80) and NMI → 019C (the break entry: saves the registers into function RAM 100C–1026).

**Main loop (022E):** the command byte must be nonzero, read the same twice, and below 2D. Then `jmp [cs:1300+2n]`. The handler ends by writing 0800, which clears the port.

| Commands | Meaning |
|---|---|
| 01–04 | write/read a byte/word at ES:BX in user memory (parameters at 0–3, data at 4) |
| 05–08 | in/out byte/word at port DX in user I/O |
| 09 | get IP CS F AX BX CX DX DS |
| 0A | get SS SP BP SI DI ES and the break status |
| 0B | GO: restore the registers, wait until 0802 bit 0 (or command 12 aborts), then `lock iret` |
| 0C | set SS SP BP SI DI ES |
| 0D | PROM checksums |
| 0E | function RAM test (also run at power-up) |
| 0F–11 | set a pointer; block read or write through it |
| 12 | no operation; also aborts GO and command 19 |
| 13, 14 | check or compute the function RAM checksums |
| 15–18 | block word/byte write/read in user memory |
| 19 | stack test loop |
| 1A, 1B | error report handshakes |
| 1C–2C | 8087: control word, load, store, environment, BCD conversion |

**0802 bit 0** is modelled as "the 2650 is halted and A7 bit 3 is set" *(inferred)*.

## Running and breaking
- **The kernel needs no system bus**, so it runs alongside the 2650. The program runs only while the 2650 waits in HALT with A7 bit 3 set.
- **A break** asserts NMI. The processor's pushes for that NMI go to the common RAM; its vector fetch at 00008–0000B is where the board takes it back into the kernel. That is the 8086 Specifics' "addresses 8, 9, A and B ... used whenever a break is generated". The 2650, if halted, gets interrupt 27 ("slave halted", code 33 in the diagnostic's octal numbering).
- **With A7 bit 3 clear,** a HALT of the 2650 gets interrupt 27 at once: the "run/pause logic" of module 15.
- **When the 2650 resumes during a run,** woken by its own interrupt (the diagnostic sleeps on the 100 ms timer), the board breaks the program with REASON1 = 00 (module 40).
- **Breakpoints** use one bit per breakpoint in the three breakpoint RAMs: 01 BK1, 02 BK2, 04 BK3, 08 SVC. A cycle matches a breakpoint when all three RAMs have its bit. Breakpoint RAM 3's index is:

  | Index bits | Meaning |
  |---|---|
  | 3–0 | A3–0 |
  | 4 | memory cycle (0 = I/O) |
  | 5 | write |
  | 6 | BK2 has occurred |
  | 7 | BK1 has occurred |

  The two "has occurred" bits are fed back from flip-flops, which is how arming is done: an armed breakpoint's entries require them. The diagnostic programs the RAMs with routine 3BF1, whose record is A19–12, A11–4, the index value and the index mask. Its sequence 33E0 must break; the out-of-order 33E8 must not.
- **Break timing:**
  - A breakpoint matched by a data cycle breaks after the *following* instruction: a write in the instruction at 4 gives PC LAST 7.
  - One matched by an opcode fetch breaks after the fetched instruction, since the 8086 prefetches during the instruction before it.
  - A write-protect violation behaves like a breakpoint.
  - A fetch from non-existent memory breaks before that instruction runs (PC LAST FEFFF, NEXT FF000).
- **Mapping RAM bits:**
  - bit 0: non-existent memory (NOMEM). REASON2 02.
  - bit 2: write protect. REASON2 04; the write is suppressed *(the suppression is inferred)*.
  - bits 1 and 3: not exercised by the diagnostic (perhaps prototype memory and the AL -S slow memory).
- **Relocation RAM:** the physical A19–A12 for each 8086 4 KB block. A15–A12 go to the program-memory boards as the address, A19–A16 onto the extended address lines (the X-bus).

## TTA interface (board I's TTA connectors; diag module 70)
- **One sample per bus cycle of the program.** Fetches are the instruction bytes as the queue hands them out, one per byte. Kernel cycles and a break's own cycles are not acquired.
- **Acquisition record** (TTA pages 68–6F, from module 70's expected table at 384B, five bytes per acquisition: pages 6F 6E 6D 6B 69):

  | Page | Contents |
  |---|---|
  | 6F, 6E, 6D | A19–16, A15–8, A7–0 |
  | 6C, 6B | D15–8, D7–0 |
  | 6A | the probe |
  | 69 | bus status |
  | 68 | activity |
- **Bus status byte (page 69).** The 8540's 8088 support decodes it with the mask/value table after `CS]ES]DS]SS]` in 160-1461:

  | Bits | Meaning |
  |---|---|
  | 0 | first byte of an instruction (`f`; without it `fs`) |
  | 3–1 | S2–S0: 000 `ia`, 001 `ir`, 010 `iw`, 011 `ht`, 100 fetch, 101 `rd`, 110 `wt` |
  | 5–4 | segment: 11 `es`, 10 `ss`, 01 `cs`, 00 `ds` |
  | 6 | `bhe`, active low |
  | 7 | `tst`, active low |

  So a first instruction byte fetched through CS is 19, a later one 18, and a write through DS is 0C, as module 70 expects.
- **Activity byte (page 68):** bit 7 `int`, bit 6 `lck` (active low), from the next table in the same ROM. Bit 0 reads 1 (module 70 expects 01 under mask 83).
- **Breaks:** a TTA trigger with its break enabled breaks the program through the board: REASON2 08, one instruction later like a breakpoint (PC LAST 14 after a trigger on the write at 0F).
- **The TTA side** of this is in `notes/tta.md` (run mode at register level).

## Status
- **Passing:** all of option 0 (modules 00–70; module 70 needs `-tta`, and is skipped without a TTA) and module 33 (the slow function RAM test), with `-ep 8086` and `-ep 8088`, with and without `-tta`. The older V1.2 of the test (16-FEB-83, on the diagnostic disc version 2.4, `062-5412-08_8501_1err_DOS50.imd`) passes option 0 too.
- **Module 31** checks the PROM checksums and passes. That confirms the dump and the even/odd interleave.
- **Module 62 (8087)** passes without an 8087. The kernel's `fnstcw` writes nothing, so the 8087 reads as absent.
- System verification completes with the board fitted.

## Open
- **Prototype modes 1/2** (A7 bits 6–5, the probe's lines), mapping RAM bits 1 and 3, wait states (jumpers P3505/P7005), port 81 bits 0–2.
- **An 8087.**
- **Software:** the only 8550 software for the board is DOS/50 V2's (the EMU.8086 disc), and V2 is lost. The 8540's OS/40 support (PDP-11, in `roms/emulator_processor/8088/`) drives the same board and can be read for the command protocol.

## The 80186/80188 emulator (8300E38, `-ep 80186` / `-ep 80188`)
**The same board set** with an 80186 (or 80188) in the probe. Sources:
- users and installation manual 061-2918-00 (Feb 1984), in `sources/bitsavers/manuals/80186/`: boards I–III as on the 8086;
- the diagnostic `186.TST` (V1.1, 13-AUG-84) on `8550_DIAG.IMD`, Select mode 18;
- its kernel PROMs 160-2525-01 (even bytes) and 160-2526-01 (odd bytes).

**From the 8086 board unchanged:** ports 80–8F (command, misc status, break reasons, SVC, PC last), the RAMINH overlay, the breakpoint/mapping/relocation RAMs, the break logic and the TTA interface.

**What differs:**
- **Master control is port 27**, with the same bits as A7.
- **MISC STATUS** identifies "4 MHz 80186" or "80188": bit 0 = 80188, as on the 8086 board.
- **The kernel is 4 KB, and only half survives.** Its checksum routine reads bytes FF8–FFF, and code jumps to 0848. The PROMs are 2 KB parts, but both were dumped as 1 KB (the bitsavers zip has the same files). We have the lower 2 KB only: commands 00–1D. The reset entry and commands 1E–3F (the 8087 support and new commands) are lost.
  - The emulator runs the surviving half and treats an entry into the lost half at high level: reset goes on to 0000:0011 as on the 8086 kernel, and the commands are acknowledged.
  - None of option 0's modules calls a lost command. Module 31 fails, checksumming "PROMS U2050 U3050", as the Z80 and 8085 boards' PROM tests do.
- **The kernel decodes by address and I/O strobes.** The 80186 drives no segment status (S3–S6 = 0), and the kernel's code shows the substitutes:
  - memory: PROM 0000–0FFF, common RAM 1000–101F (SS = 0100), function RAM 2000–2FFF (variables at 2000, command table copy at 2300);
  - the command port is read at I/O 0800, and a write to memory 0800 acknowledges it; I/O 0802 bit 0 is run granted;
  - **OUT 04 … OUT 0E** brackets accesses that go to the common RAM: GO builds the IRET frame there push by push (0429–0440) and pops it with LOCK IRET (0480–0487);
  - **a break:** the processor pushes the flags, reads the vector, then pushes CS and IP, so without segment status the board sends every write to the common RAM from the NMI until the entry's first instruction, **OUT 0E** (01E3);
  - IN 00 is the stack latch, as on the 8086; OUT 0200 is at reset.
- **PC LAST** keeps a HLT's own address while the processor is halted (modules 41, 42); the 8086 board does the same.

- **Wait states** (186.TST modules 60 and 61):
  - **Data cycles:** one wait state per data bus cycle on program memory. The CPU test times a PUSH/POP/LOOP delay with timer 1 at SP = 3FFF (each word two cycles) and needs 40 clocks per 36-clock iteration (count 1766–1779).
  - **Fetches:** they cost nothing, because the prefetcher overlaps execution. Module 61 times a fetch-only loop and needs ≤ 5C counts.
  - **Slow memory (mapping RAM bit 3, AL -S):** every cycle in a slow block, fetches included, costs the jumper-selected wait states. Module 61 needs > 5B counts there. The number is not known; 1 is used.
- **TTA:** the bus status byte has segment bits 11, since S4/S3 = 00 and the test ignores bit 4 (29/28/2C under mask AF). A TTA break arrives one instruction later than on the 8086: the test counts to 20, against the 8086 test's 22, for the same break.
- **Three bugs in MAME's 80186 peripherals fixed** (`cpu/i86/SOURCE.txt`), found by module 60:
  - the in-service register's reserved bit 1;
  - a byte read at an odd peripheral-block address returns the register's low byte;
  - POLLSTS INTREQ clears when nothing is requested.

**Status of Select mode 18, option 0:**
- **Pass:** 00–30, 32, 40, 41 (X-bus addressing), 42 (addressing/relocation), 50–57, 60 (CPU, timers, interrupt controller), 61 (wait states), 70 (TTA, with `-tta`): every module but 31, over 9 iterations.
- **Fail:**
  - **31:** the lost PROM halves.
  - Module 42 (addressing/relocation) passes since the program-memory boards are modelled. The board's relocation output A19–A16 goes onto the extended address lines, and with B8/B9 = 30 the boards' comparators answer only bank 00. The test writes 00 at 00000 and markers at 10000, 20000, 40000 and 80000, and physical 0000 must keep its 00. (Its message labels the value it found as EXPECTED.)
- **The 80188 passes the same modules.** Its CPU test is patched by the diagnostic to 585 delay iterations (0A05 = 249h) where the 80186 gets 600 (258h), with the same window. So on the 80188 an iteration takes 41 clocks against 40. Module 61's fetch-only loop rules out fetches and jumps as the cause, which leaves the data cycles.
  - **Emulated as:** a word read over the 80188's 8-bit bus costs one more clock, because execution waits for the second byte, while a write is posted *(inferred)*.
  - A first try charging the jump's refetch failed module 61, which is how the data-cycle explanation was settled.
- **Option 8 (MICROLAB modes 1/2)** needs a Tektronix MicroLab I trainer (067-0892-xx) with the 80186/80188 personality card (018-0211-00) on the probe, as the installation manual's verification describes. Module 82 runs the MicroLab's own program (it displays "HELLO"), whose ROM is not in the collection; modules 80/81 need its target RAM and clock (without them: "MODE1/2 CLOCK FAULT") and the lost kernel half's UPUT/UGET commands. Not emulated.
