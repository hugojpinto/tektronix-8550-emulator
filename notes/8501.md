# 8501 DMU — hardware notes (from 061-2355-00 + ROM disassembly)

CPU: DEC LSI-11/2 (KD11-HA), 32 KW DRAM. Addresses are octal.

## Memory map
| Range | What |
|---|---|
| 000000–167776 | RAM (top of RAM = 167776 on an 8550; the diag sizes memory via trap 4) |
| 170000–177776 | I/O page (strap: 2 KW I/O page; 160000 option for 4 KW) |
| 173000–174776 | Utility PROM window (512 words). **LTC bit 5 = 0 → diag half, 1 → boot half** |

## Devices
| Addr | Vec | Device | Notes |
|---|---|---|---|
| 177560–566 | 060 | AUXILIARY serial port (console, ODT terminal) | DL11-style RCSR/RBUF/XCSR/XBUF. XCSR 15–12 = programmable baud when bit 5 set |
| 177510–516 | 200 | PRINTER serial port | same format. Also used for "8501 COMM mode" download (bootstrap) |
| 177546 | EVNT (100) | LTC | 15–11 LEDs (0 = on, INIT = all on), 7 = 60 Hz monitor (write 0 clears), 6 = IE, 5 = PROM half select, 0 = strap |
| 177160 | 230 | Flexible disc controller CBPR | pointer to 8-word command block, see below |
| 176510 (… 176516?) | 360 | I/O board HSI (153.6 kbaud link to the 8301) | DMA control/status, counter, address, RCSR/RBUF/XCSR/XBUF-like regs. Power-up vector 060, programmable |
| 176520 + n·020 | | written with 1 by the diag init loop (8 slots) | probably local INIT of optional boards; absent → trap 4 |

Power-up/RESTART: the Utility board forces PC = 173000 (PSW 340), LTC bit 5 = 0 → diagnostics; diag sets bit 5 → bootstrap.

## Flexible disc controller (HLE target)
Command block at CBPR (written to 177160; the write starts the command):

| Off | Reg | Meaning |
|---|---|---|
| +0 | FDCR | 15 DONE (set by ctrl; host clears), 14 IE (vector 230), 13 update regs, 12 abort on disc change, 11–10 drive, 9–8 ext. address (A17–16), 7 verify on write, 6 CHAIN, 5–0 command |
| +2 | FDWCR | word count (0 = seek); for format the number of tracks (clipped to the rest of the disc; 0 = seek and set the assumed density). Status returns firmware version ×100 |
| +4 | FDDAR | record number (256-byte records); for format the first **track** (0–76 one-sided, 0–153 two-sided; past the end → "disc overflow" error, which is how FORMAT finds the end); status returns capacity |
| +6 | FDDMAR | DMA address |
| +8 | FDER | 15 hard, 14 sector not found, 13 WP, 12 capacity ovf, 11 invalid cmd, 10 DMA ovf, 9 DMA timeout, 8 ctrl timeout, 7 not formatted, 6 cmd while busy, 5 seek, 4 ID CRC, 3 data CRC, 2 self-test, 1 disc changed, 0 not ready |
| +10 | FDSR | 15 TRK00, 14 ready, 13 index, 12 disc change, 11 two-sided, 10 WP, … 4 control field |
| +12 | FDDR | diagnostic register |
| +14 | FDCHR | chain address (bit 0 = continue on hard error) |

Commands: 41 Read/Seek, 43 Write, 45 Verify, 47 Format DD, 51 Format SD, 53 Status, 55 Slow status, 57 Initialize, 61 Write control field, 63 Diagnostic (incl. load/execute Z80 RAM at 0x2080).
Capacity: SSSD 1001, SSDD 1989, DSSD 2002, **DSDD 3991** records = 13 (trk 0 side 0, 26×128 B FM) + 153×26 (256 B MFM).
⇒ record N = byte offset N·256 in the linear raw dump (`sources/raw/*.raw`), assuming no logical interleave (the boot test passes: record 0 starts with 000240).

## Bootstrap (ROM half 1) disc boot
Builds block at 001000: FDCR = 041 | drive<<10, FDWCR = 400 (256 words = records 0–1), FDDAR = 0, FDDMAR = 0. It writes 1000 to 177160, polls DONE, and fails on FDER<15>. It requires word 0 == 000240, then sets LEDs 030040 and jumps to 0. It tries drives 0–3 in turn, waiting ~6 s between rounds.
ROM strings: "DISC ERROR", "FILE ERROR", "LTC", "RAM", "HSB"/"VE." (monitor command table at 174520).
Diag (half 0) LED/LTC writes: 104000 → 174000 → … ; restart table at 173006 (REn commands).

## DOS/50 file system
Documented, with the evidence for each field, in `../tekmato/FORMAT.md`. The `tekmato` tool reads and writes it. In short:
- 512-byte blocks (2 records);
- label in block 5 (record 10);
- one 512-byte descriptor per file at block 6+id, holding extents, three times, size, consumption, capabilities, owner and link count;
- free bitmaps (1 = free) for blocks and descriptors;
- directories of 16-byte (id, 14-char name) entries; hard links are common.

Observations that matter when running DOS/50 here:
- **Time:** seconds since 1-JAN-70 on a calendar of **31-day months**. The emulated clock starts at 0 until `DATE` is set.
- **Protection:** writing into a directory you don't own without PW gives **"Error 12 Device I/O error on write"**. The distribution discs' roots are TEKTRONIX's (OR/OW/PR), so as `NO.NAME` you can only write into their subdirectories. This is not a controller fault: the FDER trace (`TEK_IOTRACE=1` now logs nonzero FDER) shows none.
- **FORMAT** (fixed 2026-11-11). It issues one format command per track (047 double density, 051 for `FORMAT:S`), FDDAR = 0, 1, 2… with no upper limit. It stops when the controller refuses the first track past the end. The HLE used to accept any track, so FORMAT ran forever and looked hung. The trace logged only read/write commands, so the hidden format stream wasn't visible at first. FORMAT then asks the status command for the capacity and sizes the volume from it: last block = records/2 − 1 (499 / 993 / 1000 / 1994), which tekmato's `-new` matches for every geometry. `FORMAT:Z` skips the track formatting.

## Disc geometry (service manual 12-9 to 12-17)
- **Formats:** IBM-compatible 8" media, 77 cylinders, 1 or 2 sides, 26 sectors per track.
  - Single density: FM, 128-byte sectors, so 13 records per track.
  - Double density: MFM, 256-byte sectors, so 26 records per track.
  - Track 0 (cylinder 0, side 0) is always FM.
- **Tracks:** logical track *t* = cylinder *t*/2, side *t*%2 on two-sided media.
- **Capacities** (status command): SSSD 1001, SSDD 1989, DSSD 2002, DSDD 3991 records. All four differ, so the emulator takes an image's geometry from its size (`fd_geometry` in `imd.h`). The IMD writer lays out each geometry's tracks.
- **Format fill:** each sector is filled with the 8 bytes *cylinder, 0, side, 0, sector, 0, density, 0* repeated. That "track" means the cylinder is an assumption.
- **Status register (FDSR):**
  - bit 11 = two-sided media;
  - bit 0 = double-density disc;
  - bit 2 = present density;
  - bit 3 = density known.
  The HLE now reports all four. Both diagnostic disks still pass with them.
- **Not modelled:**
  - mixed-density discs (a density change re-lays the whole image out);
  - the "disc not formatted" status of a truly blank disc (a zero image reads as formatted);
  - per-sector errors and retries.
