# 8501 Flexible Disc Controller (board A50) — hardware notes

Emulated low-level since 2026-11-11 (`emu/src/machine/tek8501_fdc.*`, `flexdrive.*`); the old
high-level shim remains as `-fdc hle`. The LSI-11 programming interface (CBPR, command block,
FDER/FDSR/FDDR bits) is in `8501.md` and the service manual §12; this file covers the board's
inside: what the Z80 sees.

Sources: service manual 061-2355-00 (§1 Fig. 1-9/1-11, §12, parts list), the board photo
`sources/bitsavers/photos/8501/8550_Floppy_T.jpg`, and the firmware itself
(`notes/dasm/8501_fdc.lst`).

## The board (established)
- **Photo:** "FLEXIBLE DISC CONTROLLER 670-6228". MK3880P-4 (Z80A, Tek 156-0985-01) at U2020,
  ROM **160-0412-00** at U2030, MK4801AP-4 (1K×8 SRAM) at U2040, MC4024 VCO (PLL data
  separator), all-TTL drive interface, three LEDs on the top edge.
- **Parts list** (manual line ~14745): A50U2030 = 160-0412-00, "4096 X 8 ROM". Our dump
  `roms/8550/8501/160-0412-00.u2030` is that ROM: its bytes sum to 00, which the board
  self-test at 0FB5 requires.
- **Clock 4 MHz:** the delay routine at 0267 is `C=250 × (DEC C; JR NZ)` = 4000 cycles per
  count, and the firmware's step (3), head settle (15) and head load (35) counts are then
  exactly the Qume DataTrak 8's 3 ms / 15 ms / 35 ms.

## Z80 memory map (established from the firmware)
| Address | R/W | What |
|---|---|---|
| 0000–0FFF | R | ROM 160-0412-00 |
| 2000–23FF | RW | RAM (SP = 2400). 2000 CBPR copy; 2002–2011 the command block (FDCR, FDWCR, FDDAR, FDDMAR, FDER, FDSR, FDDR, FDCHR); 2010+6·n per-drive state (track, flags, capacity) |
| 4000 | W | **HCR0** (shadow 203D): D7–D4 DS3–DS0, D3 side, D2 head load, D1 direction (1 = in), D0 step |
| 6000 | W | **HCR1** (shadow 203E): D6/D5 EA17/EA16, D4 precomp enable, D3 DMA write (1 = to memory), D1 double density, D0 precomp switch; D7/D2 diagnostic |
| 8000 | R | **HSR0**: D7 track 00, D6 ready, D5 index, D4 disc change, D3 two-sided, D2 write protect, D1 multiple interrupt (CBPR written while busy), D0 CRC error |
| A000 | R | **HSR1**: D7 DMA timeout, D6 no data detected, D5 drive not ready for R/W; D0 = 1 for normal operation (0 → board self-test, then a DMA scope loop at 0043) |
| C000 | R | arm the read/write logic (read before every ID/data operation) |
| E002 | R | **DRDR**, next disc byte (WAIT until it arrives) |
| E102 | R | DRDR with A8: wait for the next sync mark and return its byte |
| E402 | R | A10: end of field; HSR0 D0 then holds the CRC check of the bytes read since the sync |
| E000/E001/E020/E021/E041/E081/E141/E801/EA01/EF01 | W | **DWDR**, disc write data; the address bits are control (below) |
| E004/E005 | W | **DTR** (DMA data out, low/high). Written at E104/E105 (A8): the word is the interrupt vector and the LSI-11 interrupt is requested (the firmware writes 0098 = vector 230) |
| E006/E007 | W | **DMAAR**; writing the high byte starts a word DMA (direction HCR1 D3) |
| E008/E009 | R | **DRR**, the word a DMA read fetched |
| E00A/E00B | R | **CBPR** as the LSI-11 wrote it |
| E00C | R | end of command (clears busy; read just before the write-back unless chaining) |
| E00F | R | read after a successful ID match; no visible effect |
| I/O port 00 | IN | clear the status flip-flops and the interrupt (read with C000 at command start) |

Interrupts: **NMI** (0066) = the LSI-11 wrote CBPR. **INT** (IM 1, RST 38) = DMA timeout / no
data / not ready during a transfer; the handler is `SCF; RETI` and the transfer loops (run with
EI) test carry to abort. A CBPR write during the 90 ms power-up delay is deferred (flag 2043).

## Disc write control bits (established from the format and write tables)
Each DWDR write's address applies to the byte **already in the shift register** (the previous
byte), which is how the hardware pipelines a holding register in front of the serialiser:

| Bit | Meaning | Evidence |
|---|---|---|
| A11, A10, A9 | FM clock suppression: all three = C7 clock (FE/FB/F8 marks), A11+A9 = D7 (FC index mark) | FM tables: FE/FB followed by a write at EF01; FC followed by EA01 |
| A11 (MFM) | C2 mark (index mark C2 C2 C2 FC) | MFM table: C2 E001, C2 C2 E801, FC E801 |
| A6 (MFM) | A1 mark | A1 E001, A1 E141, A1 E041, FE/FB E041 |
| A8 | CRC preset at this byte | the first A1 (MFM) or the mark byte (FM) |
| A7 | send the CRC (high, then low) instead of the byte | two writes to E081 after every field |

A0 and A5 (E000 first write, data words at E020/E021) have no effect we could see; the model
ignores them. The firmware's track layout (IBM 3740 FM / System 34 MFM, no interleave, sectors
1–26, size code 0/1) is what `flex::build_track` reproduces when an image is mounted.

## Timing and status (established, with the inferred parts marked)
- 360 rpm, 8": one revolution = 666,624 Z80 cycles; FM byte = 128 cycles (250 kbit/s), MFM = 64.
- **No data detected** after two index pulses without a sync mark: "Controller timeout ... not
  begun within the required time (0.33 sec maximum)", manual §12 FDER bit 8. (The same page also
  says "0.33 mSec" for "no data"; we take the 0.33 s reading. *Inferred.*) A density probe
  on a wrong-density track therefore costs up to 0.33 s, and an **unformatted disc costs about
  2.7 s per status command** (four probes). DOS/50 polls the drives' status every few seconds,
  so an unformatted disc in a drive at boot delays the 8501 enough for the 8301 boot to fail
  ("BOOT V2.1 error?"). Insert blank discs after booting (`-mount T N=FILE`).
- **DMA timeout** 16 µs (manual); the model times out at once on non-existent memory.
- **Disc change** (HSR0 D4) is reported by the drive "since the last access". *Inferred:* it is
  cleared when the drive is deselected (the firmware deselects all drives at the end of every
  command), so a change survives until the next command's checks. Discs mounted at power-up
  start with it clear; `-mount` at run time sets it.
- **BINIT resets the Z80.** *Inferred:* the firmware's handling of a CBPR write during its
  power-up delay suggests the LSI-11 can command it right after a reset.
- Firmware version reported by STATUS: 100 (1.00). The HLE used to report 210.
- The controller's self-test and the scope loops of DIAGNOSTIC 1–4 run, but nothing in our
  software uses them. DIAGNOSTIC 5/6 load and run code in Z80 RAM at 2080; not exercised yet.

## Verified (2026-11-11)
- DOS/50 boots, LDIR; both diagnostic discs end in SYSTEM VERIFICATION COMPLETE; RTPA.TST.
- FORMAT on blank media: DSDD (1995 blocks), DSSD (1001), SSDD (994), checked by `tekmato`.
  FORMAT:S on single-sided media fails with "Error 65 Disc full" **in both models** (HLE too),
  so it is DOS/50's default of 256 files on a 500-block volume, not the controller.
- FORMAT → VERIFY (0 bad blocks) → `COPY:L:B /DEV/FLX0 /DEV/FLX1`: the copy equals the source
  except for six bytes of access time stamps that DOS/50 updated on the source.
- Track build/decode round-trips byte-exact for all four geometries.
- **IMD discs are kept track by track** (`flex::drive::load_imd`/`to_imd`, `parse_imd_tracks`/`save_imd_tracks` in `imd.h`): each IMD track's sectors go onto the byte-cell track in recorded order with their own ID fields, F8 deleted-data marks, bad data CRCs and missing data fields (IMD "unavailable"), and saving decodes the media back into exactly that. `make test` round-trips every IMD in `sources/` and a synthetic track with every kind of mark. A deleted sector survives a DOS/50 session that writes the disc (`COPY` onto an IMD mounted `-rw`). The one "unavailable" sector of `062-5412-08_8501_1err_DOS50.imd` is now unreadable on the emulated disc, as it was on the original; the diagnostic on that disc still completes.

## Limits
- Byte-cell model, not flux: no weak bits, no mixed-density tracks within one track, no
  rotational speed variation. Writing a track in the other density rebuilds it blank first.
- Raw (`.img`) images hold sector data only: deleted-data marks, CRC errors and odd layouts are
  kept on the emulated track but lost when a raw image is saved. Use IMD to keep them.
- IMD has one sector size per track; a track written with mixed sizes keeps the first size's sectors.
- Saving a raw image decodes every track; sectors that cannot be decoded are written as E5 and reported.
- Mixed density within a track, weak bits and speed variation would need a flux-level image
  format (HFE, SCP) and a flux model of the drive. Neither the 8501 nor IMD produce them.
