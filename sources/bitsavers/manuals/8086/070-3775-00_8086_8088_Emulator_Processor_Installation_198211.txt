INTRODUCTION

The 8086/8088 Emulator Processor is an accessory designed to function as part
of the 8301 Microprocessor Development Unit (MDU) or the 8540 Integration
Unit (IU). The 8086/8088 Emulator Processor provides in-circuit emulation
for an 8086 or 8088 device.
This manual contains procedures for installing the 8086/8088 Emulator
Processor in the 8301 MDU or the 8540 IU.     This manual also contains
performance verification procedures.

For user information about the 8086/8088 Emulator Processor, refer to your
System Users Manual and to the 8086/8088 Emulator Specifics supplement.
Servicing information is contained in the 8086/8088 Emulator Processor
Prototype Control Probes Service Manual.

    The 8086 or 8088 device contained within the prototype control
    probe is extremely static-sensitive.    Although this device is
    protected from static discharge damage when installed in the
    emulator processor, static discharge may interrupt the normal
    operation of the emulator if the following precautions are not
    taken:

    1.   Avoid touching the prototype control probe cables and 40-pin

    2.   Under some conditions, you may find it necessary to use an
         anti-static wrist strap while operating this equipment.

MODES OF OPERATION

The 8086/8088 Emulator Processor operates in one of three emulation modes:

MODE 0     System mode.    Mode 0 is used to develop software for a prototype
           circuit based on an 8086 or 8088 device.          In   mode O,   the
           microcomputer development system acts as a stand-alone 8086- or
           8088-based microcomputer. Thus, the prototype software is stored in
           your development system's program memory, and the 8086/8088 Emulator
           Processor provides the I/O facilities and clock.         Figure 1-1A
           illustrates mode 0 operation.

MODE 1 Partial emulation mode. Mode     is used to develop some of the
       hardware   functions of the prototype circuit.       In mode 1, the
       prototype control probe is connected between the 8086/8088 Emulator
       Processor boards and the microprocessor socket of the prototype
       circuit. In this way, the prototype's memory, I/O, and clock are
       exercised, while the development system retains full control over the
       prototype system.

           In mode 1, the memory mapping feature allows various portions of the
           prototype software to be stored in prototype memory while the rest of
           the prototype software remains in the development system's program
           memory. Figure 1-1B illustrates mode 1 operation.
MODE 2     Full emulation mode. Mode 2 is used in the final software/hardware
           integration phases of prototype system design, or is used when
           troubleshooting hardware with known-good      software.  The   only
           difference between mode 1 and mode 2 is that here, the entire
           prototype program is stored in the prototype's memory.  Figure 1-1C
           illustrates mode 2 operation.

EMULATOR PROCESSOR OVERVIEW
The 8086/8088 Emulator Processor consists of three circuit boards and either
an 8086 or 8088 Prototype Control Probe. The three circuit boards plug into
the microcomputer development system mainframe, and the prototype control
probe attaches to one of the three circuit boards.
The 8086/8088 Emulator Processor serves two purposes in the microcomputer
development system.    First, the emulator has the ability to run a program
written specifically for the target microprocessor. With the help of other
boards in the system, the emulator processor can check the program for
run-time errors or program logic errors. Second, with the prototype control
probe connected between the emulator processor boards and the prototype
circuit, the prototype circuit can be debugged and stepped through the final
stages to design completion.
The 8086/8088 Emulator Processor emulates the operation of a         target
microprocessor device that will be used in the final version of a prototype
system. The emulator processor responds to software in the same way as the
target microprocessor, and also allows software debugging.


EMULATOR PROCESSOR BOARDS

The three 8086/8088 Emulator Processor boards plug into the main interconnect
board of the system mainframe. These boards are designated as board I, II,
and III. The functions of each of these boards are as follows:

Board I     contains breakpoint circuitry, clocks, address and data strobes,
            and the TTA connectors.
Board II    contains the address latch and buffer, the prototype control probe
            interface, mainframe interface timing, the queue, Mapping RAM, and
            Relocation RAM.
Board III   contains the data bus interface, PROM, Function RAM, Command Port,
            Status Port, and Master Register.

PROTOTYPE CONTROL PROBE
The prototype control probe allows an emulator processor to functionally
replace the microprocessor of a prototype system. The probe is the interface
between the emulator processor boards and         the  prototype   circuit's
microprocessor socket.
The prototype control probe consists of:
1.      Two 6-foot ribbon cables that attach to a cable termination board, which
        plugs into 8086/8088 Emulator Processor board II.
2.      An interface assembly, which contains the Buffer board, the Control
        board, the Power Supply board, and an 8086 or 8088 Mobile Microprocessor
        board.
3.      A 40-pin dual in-line plug that inserts in the microprocessor socket of
        the prototype circuit. The plug is connected to the interface assembly
        via two 1.5 foot ribbon cables.
Figure 1-2 shows 8086/8088 Emulator Processor interconnections.

Prototype Control Probe LEDs
Six indicator LEDs are visible on the prototype control probe's           interface
assembly. When lit, these LEDs indicate the following conditions:
RESET         The prototype circuit has asserted the RESET line and caused       the
              processor to stop current activity.
TEST          The prototype circuit has asserted the TEST line.   (This    LED    is
              always lit in mode 0.)

WAIT           The processor is in a wait state.
BUS ACK        The processor is acknowledging a bus request.
SELECT         The emulator processor has been selected.
PROTOTYPE POWER -- The prototype circuit's +5 V supply is present.

In order to access these jumpers you must disassemble the housing of the
interface assembly and, in most cases, also remove the Control board located
inside the housing.   Refer to the discussion, "Accessing the Prototype
Control Probe Jumpers", later in this section.

CONTROL BOARD JUMPERS

P2    Outread option. Basically, the outread option enables data out to the
      prototype circuit that has been read from program memory or mapped-in
      memory.   Sending this data to the prototype allows        a  prototype
      coprocessor (such as the 8087) to follow program flow.

      When this jumper is in position 1, the outread option is not selected and
      the emulator functions normally. This is the normal jumper position.
      When this jumper is set in position 2, the outread option is enabled.
      Position 2 must be selected whenever a coprocessor is used in the
      prototype circuit during mode 1 operation. Note that in order to use the
      outread option, the prototype circuit's data buffers must be designed to
      disable during outreads.

P3    DMA disable option. When this jumper is set to position 2, DMA (RQ/GT)
      operations while the emulator is in mode 3 are enabled. (Mode 3 is not a
      true emulation mode, but encompasses all emulator activity that occurs
      while the emulator is not executing a prototype program.)   This is the
      normal position and must be selected if DMA operations continuously need
      to be used by the prototype circuit (for CRT refresh, for example).

      When this jumper is set to position 1, all DMA operations during mode 3
      are disabled.    This jumper setting ensures stable memory data or status
      during mode 3 and must be selected if you want to use the D (Dump) or EX
      (Examine) command to inspect memory affected by DMA operations.

P4    Hold timeout option. When this jumper is set to position 2, the emulator
      will wait indefinitely for the current DMA cycle to end before any break
      request is honored. This is the normal jumper position.
      When this jumper is set to position 1, any break request will start a
      timeout that lasts for about 0.5 second of DMA access. At the end of the
      timeout, the break request is honored. If the jumper is set to this
      position, jumper P3 must also be set to position 1.

P5    Clock deskewer enable. When this jumper is set to position 1 ("DESKEW"),
      the clock deskewer circuit is enabled. This is the normal position. If
      you select this position, be sure to set jumper P8 to the appropriate
      position.

P6012   Synchronize RESET option. This option synchronizes the RESET signal
        from the prototype circuit with emulator bus cycles in order to
        minimize the likelihood of writing randomly to memory.

        When this jumper is set to position 1, this option is disabled and the
        RESET signal from the prototype circuit is transparently emulated.
        This is the normal position.

        When this jumper is set to position 2, the synchronize RESET option is
        enabled.

P7072   Prototype READY control. When this jumper is set to position 2, the
        prototype's READY signal does not control mode 1 access to program
        memory. This is the normal jumper setting and should be selected for
        full-speed operation of program memory while in mode 1.

        Position 2 should also be selected if the prototype circuit is in a
        system (such as a Multi-Bus) where nonexistent memory accesses produce
        a not-ready status. In such a case, the READY line would become stuck
        and the system would hang.       (This feature is necessary because a
        mode 1 program memory access of a particular address also produces an
        access of the same address in prototype memory. However, the data
        accessed in prototype memory under these circumstances is never read.)

        When this jumper is set to position 1, the prototype's READY signal
        controls mode 1 access to program memory. This position may be needed
        if prototype memory control circuitry requires that wait states be
        inserted to avoid memory or memory controller destructive states.
        (Again, this feature is necessary because of memory bus cycles that
        occur simultaneously in program memory and prototype memory.)

The following procedure tells how to disassemble the interface           assembly      in
order to gain access to jumpers in the prototype control probe.

2.   Remove the four screws that    secure    the   top   cover   of   the     interface
     assembly's plastic housing.

     not to pull any of the cables loose that connect the bottom cover to the
     rest of the interface assembly.

     self-locking nuts    that secure the metal shield, then lift off the
     shield.

5.   Remove the six metal spacers. Carefully lift the top circuit board (the
     Control board) from its supporting posts, and then flip the board over
     on its connecting cable so that both the Control and Buffer boards are
     now exposed.

GROUNDING

A proper ground system is necessary for the satisfactory operation of the
8301 MDU or 8540 IU.       The emulator processor board and prototype control
probe, as well as any other optional and peripheral equipment, must be
properly grounded to eliminate ground loops and prevent static discharge

INTRODUCTION

After the 8086/8088 Emulator Processor has been installed in your development
system, it should be checked for proper operation. The first part of this
section discusses equipment necessary to generally verify that the emulator
processor is operating properly. The second part of this section discusses
equipment necessary to verify timing relationships of signals at the pins of
the prototype control probe.

Every time you install an emulator processor, you should run system
verification checks. Emulator processor diagnostics are run automatically as
part of the system diagnostic test program.    Procedures for running this
diagnostic test program are included in your system's Installation Guide.

EQUIPMENT REQUIRED

To check the operation of the installed   8086/8088     Emulator   Processor,   the
following equipment is required:

      e   TEKTRONIX MicroLab I (067-0892-xx).

      •   8086/8088 Personality Card
The MicroLab I checks the 8086/8088 Emulator Processor by providing a circuit
with known characteristics (the personality card). The personality card is
monitored by MicroLab I circuitry, and test results are indicated on the
MicroLab I display. The MicroLab I operating system also contains tests that
functionally exercise the prototype control probe.

Throughout this section it is assumed that you are familiar with the
MicroLab I and its characteristics. For more information on this equipment,
refer to the MicroLab I Instruction Manual and the 8086/8088 Personality Card
supplement.

EMULATOR TIMING VERIFICATION
You may occasionally want to verify timing relationships between the signals
at the pins of the prototype control probe. The following paragraphs discuss
equipment necessary to perform these timing verifications.
Details of these timing relationships are provided            in     the        appropriate
Emulator Specifics section of your System Users Manual.


MEASUREMENT CONSIDERATIONS

Emulator timing verification involves measurement of extremely fast signals.
Test equipment used for these measurements should be able to resolve timing
differences of less than 5 ns between two signals. A resolution of 1 ns is
best for examining the most critical timings.




4-4
                        Performance Verification - 8086/8088 E.P. Installation


Be careful that errors are not introduced by the test equipment being used.
Test equipment calibration should be checked carefully. If you are using a
dual trace oscilloscope rather than a dual beam model, be sure to account for
any possible skew between the the two input channels. In general, good
laboratory measurement practices should should be followed to ensure accurate
results.

Equipment Required

To measure timing relationships with the preferred accuracy      and   resolution,
the following equipment may be used:
      •   TEKTRONIX 7844 Dual Beam Oscilloscope, or equivalent

      •   Two TEKTRONIX 7A26 Vertical Amplifiers, or equivalent

      •   TEKTRONIX 7B85 Delaying Time Base, or equivalent



CONTROLLING THE SIGNAL LINES UNDER TEST
Some processor signal lines, such as interrupt lines, are normally connected
to asynchronous circuits. Timing relationships of asynchronous signals may
be difficult to measure with an oscilloscope. To exercise these signal lines
in a periodic manner, it may be necessary to develop software routines or use
an external test fixture such as the TEKTRONIX MicroLab I.
